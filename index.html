P0 Phase 0 — OS & Lab Setup (Week 1–3)

Foundation first. A hacker who can't use the terminal and doesn't understand the OS is just a script kiddie.

Goal: Install Kali Linux, get comfortable in the terminal, set up a safe home lab with vulnerable machines.
KL
Kali Linux FREE
Attacking OS — Debian-based

The industry-standard Linux distribution for penetration testing. Comes with 600+ security tools pre-installed. This is your main working OS for the whole roadmap.

When: Always. Install it first, learn to live in it.

Download: kali.org/get-kali (VM image recommended)
Login: kali / kali (change password first!)
kali.org →
VB
VirtualBox FREE
Virtualization — Lab host

Runs Kali + vulnerable target machines safely inside your laptop. If you break a VM, you delete it and make a new one — your real PC is never at risk.

When: Day 1. Set network mode to "Host-Only" so lab machines stay isolated from the internet.

Setup: New VM → 2GB+ RAM, 2 CPUs, 20GB disk
Network: Host-Only Adapter (lab isolation)
virtualbox.org →
VM
VMware Workstation Player FREE
Virtualization — Alternative to VirtualBox

Smoother performance and better USB/WiFi adapter passthrough than VirtualBox. For wireless hacking (Phase 5), VMware handles external adapters more reliably.

When: Use either this or VirtualBox — you don't need both.

vmware.com →
LX
Linux Terminal FREE
Skill — Non-negotiable

Your bread and butter. Filesystem hierarchy (/etc, /var, /home), permissions (rwx, chmod, chown), users, sudo, processes. Aim to do daily tasks without the mouse.

When: Every single day, for the rest of your career.

cd / ls -la / pwd          # move & inspect
grep -rn "text" /folder   # search inside files
find / -name "*.conf" 2>/dev/null
chmod +x script.sh        # make executable
ps aux | grep ssh         # running processes
Practice free at linuxjourney.com →
$H
Bash Scripting FREE
Automation — Shell

Repetitive hacking steps (scanning many IPs, parsing output, quick loops) become one script. Start with variables, if/else, for loops.

When: The moment you type the same command 3 times — script it.

#!/bin/bash
for ip in $(cat targets.txt); do
  nmap -sV -oN "scan_$ip.txt" "$ip"
done
PY
Python FREE
Scripting — Tool building

The language of security tooling. Build your own port scanner, brute-forcer, or log parser — employers love candidates who can script. Learn: sockets, requests, subprocess, argparse.

When: Phase 2 onwards; every pentester's automation edge.

import socket

s.settimeout(0.5)
if s.connect_ex(("10.10.10.5", 80)) == 0:
    print("Port 80 OPEN")

P1 Phase 1 — Networking & Recon (Week 3–8)

"A month of recon saves a year of exploitation." Hacking is mostly understanding how data moves — then finding where it leaks.

Goal: Master Nmap + Wireshark, understand TCP/IP and DNS deeply, learn to map a target (in your lab / authorized scope only).
WS
Wireshark FREE
Traffic analysis — Packet capture

Captures and dissects live network traffic packet by packet. Teaches you what really happens on the wire: handshakes, DNS queries, credentials in plain protocols. The best learning tool in this entire roadmap.

When: Learning protocols, analyzing lab captures, investigating "what did that tool actually do?"

Filters: tcp.port == 80 | dns | http.request
|| (ip.addr == 10.10.10.5)
wireshark.org →
NM
Nmap FREE
The #1 recon tool — Port & service scanner

The most used hacking tool in the world. Discovers live hosts, open ports, running services, versions, and even vulnerabilities via NSE scripts. Every pentest starts here.

When: First contact with any lab target — always scan before you attack.

nmap -sV -sC 10.10.10.5        # versions + scripts
nmap -p- 10.10.10.5             # all 65535 ports
nmap -sU --top-ports 100 10.10.10.5   # UDP
nmap --script vuln 10.10.10.5    # vuln scripts
nmap -sV -oN scan.txt 10.10.10.5 # save output
nmap.org →
NC
Netcat FREE
Swiss-army knife — TCP/UDP

Reads and writes raw data across network connections. Banner grabbing, simple file transfers, quick listener shells — and it's how reverse shells actually work under the hood.

When: Checking a service manually, testing connectivity, catching lab reverse shells.

nc -nv 10.10.10.5 22          # banner grab
nc -lvnp 4444                 # listener for lab shell
DG
dig / whois / dnsenum FREE
DNS & domain recon

DNS tells you a target's infrastructure: mail servers, nameservers, subdomains, TXT records. dig for queries, whois for registration data, dnsenum for subdomain brute-forcing.

When: Web-target recon — before touching the website itself.

dig example.com ANY
dig -x 1.2.3.4                # reverse lookup
whois example.com
dnsenum example.com
TH
theHarvester FREE
OSINT — Emails & subdomains

Collects public emails, names, subdomains and hosts from search engines and public sources. This is passive recon — no packets touch the target.

When: Pre-engagement research and CTF OSINT challenges.

theHarvester -d example.com -b google,bing -l 100
GO
Google Dorking FREE
OSINT — Search operators

Advanced search operators that surface exposed files, login pages, and directories indexed by Google. Also your best free documentation-finder while learning.

When: OSINT challenges, and daily — to find docs and examples faster.

site:example.com filetype:pdf
inurl:admin site:example.com
"index of" /backup
GHDB — Google Hacking Database →
SD
Shodan FREE tier
OSINT — Internet-wide device search

A search engine for internet-connected devices: exposed cameras, servers, databases. Understanding it teaches you how exposed the real world is. Search your OWN devices to learn.

When: OSINT learning; checking your own authorized infrastructure.

shodan search 'apache country:"IN"'
# Web: shodan.io (free account)
shodan.io →
RN
Recon-ng FREE
OSINT — Framework

Metasploit-style framework for recon: modules for subdomains, contacts, hosts. Organizes OSINT findings in a database instead of scattered terminal output.

When: Bigger recon tasks where manual commands get messy.

recon-ng
> marketplace install all

P2 Phase 2 — Web Application Hacking (Week 8–20)

Where most bug bounties live. You learn the OWASP Top 10 by breaking them — legally — in DVWA, Juice Shop, and PortSwigger's labs.

Goal: Master Burp Suite, understand each OWASP Top 10 vulnerability, exploit and also FIX each one.
BS
Burp Suite Community Pro
The web-hacking workbench

Intercepts every request your browser makes so you can inspect and modify it before it reaches the server. Repeater for manual testing, Intruder for automated attacks, Decoder for encodings. The single most important web tool.

When: Every web target, every time. Proxy on, browser through it, walk the whole app first.

Setup: Proxy → listen 127.0.0.1:8080
Browser: FoxyProxy → Burp → install CA cert
Workflow: Proxy (capture) → Repeater (test) → Intruder (automate)
portswigger.net →
ZP
OWASP ZAP FREE
Burp alternative — Open source

The free, open-source proxy from OWASP. Slightly less polished than Burp Pro but fully capable, with an automated scanner that Burp Community lacks. Great on a student budget.

When: You want automated scanning without paying for Burp Pro.

zaproxy.org →
SQ
sqlmap FREE
SQL injection — Automated

Takes a request you've confirmed is injectable (via Burp) and automates extraction: databases, tables, credentials. Always find the injection manually first — sqlmap is the extractor, not the finder.

When: Confirmed SQLi in your lab target. Try manual UNION attacks first to truly understand it.

sqlmap -u "http://10.10.10.5/item.php?id=1" --batch --dbs
sqlmap -r request.txt --dump -T users   # from Burp request
github →
NI
Nikto FREE
Web server scanner

Quick first-pass web scanner: finds outdated software, dangerous files, misconfigurations. Noisy and basic — it's a starting checklist, never your only test.

When: First 2 minutes against a new lab web server.

nikto -h http://10.10.10.5
FF
Gobuster / ffuf / dirsearch FREE
Directory & path brute-forcing

Finds hidden paths and files (/admin, /backup.zip, /api) using wordlists. The technique behind most "information disclosure" findings in CTFs and real reports.

When: Every web box. Also learn the wordlist dir: /usr/share/wordlists/.

gobuster dir -u http://10.10.10.5 -w /usr/share/wordlists/dirb/common.txt
ffuf -u http://10.10.10.5/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-small-words.txt
CU
curl FREE
Command-line HTTP client

Sends crafted HTTP requests from the terminal without a browser: headers, cookies, POST bodies. Every API test you'll ever do starts with a curl command.

When: Quick endpoint checks, API testing, reproducing findings for reports.

curl -i http://10.10.10.5/admin
curl -X POST -d "user=admin" http://10.10.10.5/login
curl -H "X-Forwarded-For: 127.0.0.1" http://10.10.10.5/
PM
Postman FREE tier
API testing workbench

Organized API testing: collections, environments, saved auth tokens. Modern apps expose APIs everywhere, and API bugs (IDOR, broken auth) are top bug bounty categories.

When: Any target with an API — web or mobile app backends.

postman.com →
OW
OWASP Top 10 FREE
Knowledge — Not a tool, a syllabus

Your study plan for this phase: Broken Access Control, Injection, Cryptographic Failures, SSRF, Misconfiguration... Learn each by exploiting it in a lab AND by writing the fix.

When: Constantly. One vulnerability class per week.

owasp.org Top 10 → PortSwigger free labs →

P3 Phase 3 — Exploitation & Password Attacks (Week 20–32)

You have a shell. Now what? Understanding exploits, cracking credentials, and moving through lab machines like a real pentester.

Goal: Use Metasploit competently, crack hashes you legally captured, and read/understand public exploit code.
MS
Metasploit Framework FREE
Exploitation framework

Thousands of ready exploits + post-exploitation modules in one console. Learn it properly — search, exploit selection, payload choice (bind/reverse), meterpreter — because "metasploitable" alone doesn't make you a pentester.

When: Lab machines and authorized engagements. Understand what the module does BEFORE running it.

msfconsole
search type:exploit vsftpd
use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS 10.10.10.5 && run
metasploit.com →
ED
Exploit-DB / searchsploit FREE
Public exploit database

Offline-searchable archive of 50,000+ public exploits. The workflow of a real pentester: Nmap finds vsftpd 2.3.4 → searchsploit vsftpd → read the exploit → understand → run (in lab).

When: Every time a scan shows old software. Reading the code is the education.

searchsploit apache 2.4
searchsploit -m 40974.py   # copy exploit locally
exploit-db.com →
JR
John the Ripper FREE
Password cracking

Cracks password hashes offline with wordlists and mangling rules. First learn hash identification (MD5 vs SHA vs NTLM), then cracking. /etc/shadow hashes from your OWN lab only.

When: You captured hashes from your lab machine (unshadow → john).

unshadow passwd.txt shadow.txt > hashes.txt
john hashes.txt --wordlist=/usr/share/wordlists/rockyou.txt
HC
hashcat FREE
GPU password cracking

GPU-accelerated cracking — hundreds of times faster than John on capable hardware. Learn the -m hash-type flag, attack modes (dictionary, mask, rule), and benchmarking.

When: Large hash lists in lab/CTF; understanding real-world crack speeds.

hashcat -m 1000 ntlm.txt rockyou.txt
hashcat -m 0 hash.txt -a 3 ?u?l?l?l?d?d?d?d  # mask attack
hashcat.net →
HY
Hydra FREE
Online brute-forcing

Attacks live login services (SSH, FTP, web forms) with wordlists. Because it touches a live service, it's slower, noisy — and ONLY for your own lab. Understand why rate-limiting defeats it (that's the defensive lesson).

When: Lab boxes with login services. Never against anything you don't own.

hydra -l admin -P rockyou.txt 10.10.10.5 ssh
hydra -l admin -P rockyou.txt 10.10.10.5 http-post-form "/login:user=^USER^&pass=^PASS^:incorrect"
MK
Mimikatz FREE
Windows credential extraction (concept)

The tool that changed Windows security: extracts plaintext passwords and Kerberos tickets from memory. You'll meet it in AD labs and every Windows security course. Know what it does and how defenders detect it.

When: Windows lab privilege escalation — understanding, not just running.

privilege::debug
sekurlsa::logonpasswords   # lab domain only

P4 Phase 4 — Privilege Escalation & Active Directory (Week 32–48)

The difference between a script kiddie and a professional: what you do AFTER the first shell. And where enterprise hacking really happens — Active Directory.

Goal: Escalate from a normal user to root/ SYSTEM on lab machines, and attack a home-built AD lab.
PE
LinPEAS / WinPEAS FREE
Privilege escalation enumeration

Automates the hunt for privilege escalation paths: SUID binaries, writable paths, stored credentials, services. Run it, then manually verify every "red" finding — that's how you learn the actual techniques.

When: First 5 minutes after getting a lab shell.

# On target (lab):
./linpeas.sh
./winPEASx64.exe
github →
GT
GTFOBins / LOLBAS FREE
Abusable binaries database

Encyclopedias of ordinary Linux/Windows programs that can be abused to escalate or execute (sudo vim, SUID find...). Pair with your PEAS output: it tells you WHY something is dangerous.

When: Every privesc hunt — look up every finding here.

gtfobins.github.io → lolbas-project →
BH
BloodHound FREE
Active Directory attack paths

Maps an AD domain as a graph and shows hidden attack paths: "this user → that group → Domain Admin". The defining tool of modern internal pentesting. Build a home AD lab (2 VMs: 1 Server, 1 client) to practice legally.

When: AD labs (TryHackMe "Attacktive Directory", HTB Forest/Sauna).

SharpHound.exe -c All
# then import .zip into BloodHound GUI, use prebuilt queries
github →
IM
Impacket suite FREE
Windows protocol toolkit

Python libraries for Windows protocols: SMB, MSSQL, Kerberos. psexec.py (remote execution), secretsdump.py (credential dumping), GetUserNP.py (AS-REP roast). The AD pentester's daily driver.

When: AD labs — after you have credentials or a foothold.

impacket-psexec user:pass@10.10.10.5
impacket-secretsdump user:pass@10.10.10.5
impacket-GetNPUsers domain/ -no-pass -usersfile users.txt
github →
CH
Chisel FREE
Tunneling & pivoting

Creates tunnels through a compromised lab machine so you can reach networks behind it — the "what's next" after exploiting a DMZ host. Understanding pivoting separates box-solvers from pentesters.

When: Multi-machine lab networks (HTB Pro Labs, THM Wandering amit).

# target:  ./chisel client 10.10.14.2:8000 R:socks

P5 Phase 5 — Wireless, Mobile & API (Elective, Week 48+)

Specializations. Pick the one your local market wants — mobile security is booming in India.

Goal: One specialization practiced deeply — not all three shallowly.
AC
Aircrack-ng FREE
WiFi security testing

Cracks WEP/WPA handshakes captured from YOUR OWN test router. Teaches you exactly why WPA2's 4-way handshake can be attacked and why WPA3 matters. Requires an external WiFi adapter (monitor mode).

When: Your own home router lab ONLY — testing others' WiFi is a crime in India (Sec. 66).

airodump-ng wlan0mon          # see your own network
aircrack-ng capture.cap -w rockyou.txt
aircrack-ng.org →
MF
MobSF FREE
Mobile app security scanner

Automated static + dynamic analysis of Android/iOS apps: hard-coded keys, insecure storage, weak TLS. The entry point to mobile pentesting — most Indian companies have an app that needs exactly this.

When: Analyzing apps you own/developed, bug bounty mobile scopes, or your own app before release.

mobsfscan app.apk      # CLI
# or run MobSF docker and upload APK in web UI
github →
AJ
apktool + jadx FREE
Android reversing

apktool unpacks an APK into readable resources; jadx decompiles the DEX code back to Java. Together you can read almost any (authorized) Android app's logic and find secrets.

When: Mobile bug bounty: hardcoded API keys, hidden endpoints, broken checks.

apktool d app.apk -o out/
jadx-gui app.apj   # or: jadx app.apk -d out/

⚖ Government Guidelines & the Law (India)

Ethical hacking is legal in India — WITH authorization. Know exactly where the line is.

1. Information Technology Act, 2000 — the sections that matter

India's core cyber law. The parts every student must know:

Section 43: Penalty for unauthorized access, damage, or downloading data from someone else's computer — civil liability, compensation up to ₹1 crore.

Section 66: The criminal version — "dishonestly or fraudulently" doing what Sec. 43 covers means imprisonment up to 3 years and/or fine up to ₹5 lakh. "I was just testing" is NOT a defense without authorization.

Section 66C: Identity theft (using someone's digital identity) — up to 3 years.

Section 66D: Cheating by personation online (fake profiles, phishing for fraud) — up to 3 years.

Section 66F: Cyber terrorism — life imprisonment. Never, ever touch critical infrastructure.

Section 70: Protected systems — government/CII computers are off-limits, period.

Section 72: Breach of confidentiality/privacy — publishing someone's private data.

2. CERT-In Directions, 2022 (MeitY) — for professionals

These apply to organizations you'll audit, so know them for interviews and compliance work:

6-hour rule: Report specified cyber incidents to CERT-In within 6 hours of noticing.

Log retention: Systems must keep logs for 180 days within India.

Time sync: Systems must use NICSPL/NPL time servers.

As a pentester you'll often be hired BECAUSE of compliance: RBI mandates periodic VA/PT for banks and payment systems, SEBI for market infrastructure. Compliance work = jobs.

3. DPDP Act, 2023 — data protection basics

India's data protection law (analogous to GDPR). Two angles for you:

As a learner: Never store or share real personal data you encounter while testing — even in a lab report.

As a professional: Pentest reports themselves contain personal data; secure handling is part of the job.

4. If you become a victim (or witness one)

Report: National Cyber Crime Reporting Portal — cybercrime.gov.in (also handles cybercrime against women/children on priority)

Helpline: 1930 (financial cyber fraud — call immediately to freeze funds)

CERT-In: cert-in.org.in — incident reporting for organizations

Free govt learning: ISEA (Information Security Education & Awareness) — isea.gov.in; NIELIT courses — nielit.gov.in

5. The safe practice checklist (memorize this)

Legal: your own lab VMs • CTF platforms (THM/HTB/VulnHub) • published bug bounty scope • written client authorization (get-out clause: "client name, dates, IP ranges, allowed techniques").

Illegal, always: scanning random public IPs • testing your college/office network without written permission • "checking security" of a website you don't own • brute-forcing any real account.
